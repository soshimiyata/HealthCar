# 設計・構成意図

## Q. なぜ論理削除ではなく物理削除？

論理削除は監査ログや復元が必要なシステムで有効である。

しかし、このアプリはあくまでもユーザーの個人使用であり、  
管理者が強制的に退会させるなどの行為がないため、論理削除でデータを残す必要がない。

そのため、物理削除でDB的にも負担が少ないようにしている。

## Q. なぜ Tailwind を採用？

React等は学習コストが高く、
今回はSpring BootのREST APIや設計力を見せることを優先した。

そのため

- Spring Boot
- HTML
- Tailwind
- JavaScript(fetch)

というシンプルな構成にした。
